# Atlas: контент и офлайн-релиз v2

## Единые команды подготовки

1. `GENERATE_ALL_WINDOWS.bat` — находит и генерирует все основные, дополнительные, городские и страновые аудиозаписи.
2. `DOWNLOAD_PHOTOS_WINDOWS.bat` — находит и докачивает все фотографии точек интереса.
3. `DOWNLOAD_ALL_MAPS_WINDOWS.bat` — находит и готовит PMTiles для всех достопримечательностей.
4. `PACK_MEDIA_WINDOWS.bat` — проверяет полноту и создаёт `atlas-media.zip`.

Числа не зашиты в скрипты. Они каждый раз вычисляются из `content/`, поэтому новая страна или город автоматически попадают в обработку.

## Файловая модель

```text
content/
  catalog.json
  countries/<country>/
    manifest.json
    stories/
      manifest.json
      episodes/<story>.txt
      audio/<story>.mp3                 # генерируется, не хранится в Git
    cities/<city>/
      manifest.json
      stories/...
      attractions/<attraction>/
        manifest.json
        map.pmtiles                     # генерируется, не хранится в Git
        map-plan.svg
        programs/full.json
        programs/must-see.json
        points/<point>/
          meta.json
          main.txt
          learn_more.txt
          photo.jpg                     # скачивается, не хранится в Git
          audio/main.mp3                # генерируется, не хранится в Git
          audio/learn_more.mp3
```

Статический сайт не может перечислять папки на сервере. `tools/build_content.py` сканирует дерево, проверяет ID и ссылки и создаёт каталог и городские пакеты в `content-data/`. Менять код приложения при добавлении контента не требуется.

## Публикация

1. Закоммитить исходные тексты, JSON и код в `main`.
2. Создать новый GitHub Release с очередным числовым тегом: `media-v2`, `media-v3`, `media-v3.1` и т. п.
3. Прикрепить к нему файл со стабильным именем `atlas-media.zip`.
4. Публикация запустится автоматически. При обычном push в `main` или ручном запуске workflow сам найдёт последний опубликованный, не черновой и не prerelease-тег `media-v*`.

Workflow проверяет контрольные суммы, соответствие ревизии текста и наличие каждого объявленного MP3, фото и PMTiles. Неполный архив не публикуется.

Версия не зашита в веб-приложение. Во время сборки создаётся `content-data/build-info.json` с найденным тегом медиа-релиза, ревизией контента, Git commit и отпечатком архива. Эти данные видны в менеджере «Офлайн». Из них также формируется уникальное имя shell-кэша service worker, поэтому новая публикация не остаётся на старом коде. Если заменить asset внутри уже опубликованного релиза, нужно вручную запустить `Actions → Publish Atlas → Run workflow`; предпочтительнее выпускать новый тег, чтобы версия оставалась однозначной.

## Как работает офлайн на телефоне

Пользователь открывает менеджер «Офлайн» и скачивает конкретный город. При первом городе страны приложение сначала ставит его зависимость — общий пакет страны. При установке второго города общие файлы повторно не скачиваются. Удаление города освобождает только его файлы; общий пакет удаляется после удаления последнего города этой страны.

Кэш проверяется по размеру и SHA-256. Незавершённая загрузка не отмечается как установленная, а повторный запуск продолжает с уже проверенных файлов.
