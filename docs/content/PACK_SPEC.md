# Контракт текстовых контент-пакетов v2 — предварительный

## Задача

Одна страна содержит общие сведения и отдельные городские пакеты. Каждая экскурсия содержит остановки с двумя независимыми текстами (`main` и `learn_more`) и двумя порядками воспроизведения (`full`, `must-see`). Радио не запускается по GPS.

## Идентификаторы

- Country: `egypt`; shared package: `egypt-common`.
- City: `cairo`, `luxor`, `alexandria`; package: `egypt-<city>`.
- Tour: старый ID `karnak`, `giza`, `gem` и т.д.
- Stop: **старый ID** `KAR-04`, `LUX-X01` и т.д. Не переименовывать при миграции без таблицы соответствия.
- Radio: действующие ID перечислены в `RADIO_INDEX.md`; часть старых P-выпусков исключена из пользовательских пакетов по редакционной политике. Суффикс R — импорт старых радиоисторий; P — практика; C — познавательное. Старые исключённые ID не переиспользовать.

## Схема установки контента (для будущего приложения)

1. Пользователь нажимает «Скачать Каир».
2. Каталог находит `egypt-cairo.requires=[egypt-common]`.
3. Проверяет локальный manifest + версию и наличие файлов `egypt-common`; скачивает общий пакет **только если нужен**.
4. Скачивает пакет `egypt-cairo`. В его ZIP только город, общие истории не дублируются.
5. Приложение отмечает готовность после проверки полного списка файлов/контрольных сумм; при частичном скачивании не утверждает, что всё доступно офлайн.
6. Если пользователь позже выбирает Луксор — `egypt-common` остаётся, загружается только `egypt-luxor`.
7. Удаление одного города не должно удалять `egypt-common`, пока его используют другие установленные города. Можно считать зависимости либо хранить отметки установленных пакетов.

## Дополнительные медиа

После проверки текстов отдельные build-процессы могут брать имена и ID из manifest, генерировать MP3 и собирать городские фото/тайлы. Не надо делать вид, что MP3 автоматически генерируются текущим скриптом. Путь к аудио в этой версии отсутствует намеренно.

## Обновления и кэш

Для будущей интеграции необходимы версии пакетов, атомарная замена, детерминированные имена, файлные хэши и проверка доступной памяти iOS. `revision` сейчас лишь черновая метка, не готовый механизм версионирования.

## Безопасность и качество

Не включать автоматический GPS-запуск радио. В аудиосценарии не добавлять временные визовые, музейные и транспортные правила, билеты, цены и формальные процедуры. Практические истории должны опираться на долговечные принципы, а исторические утверждения — проходить отдельную проверку источников. Если позднее появится необязательная карточка с оперативными правилами, для неё потребуются `last_verified_at`, официальный источник и механизм обновления, отдельно от MP3. Отсутствие интернета не должно выдавать старые цены/правила за актуальные. См. `EDITORIAL_POLICY_EVERGREEN_2026-11-09.md`.
