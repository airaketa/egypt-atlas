# Расширяемая контентная архитектура Atlas

Приложение не содержит списков стран, городов или достопримечательностей в JavaScript. Источник истины — папка `content/`.

## Иерархия

- страна содержит общий пакет историй и ссылки на города;
- город содержит городской пакет историй и список достопримечательностей;
- достопримечательность содержит программы осмотра, карту и точки интереса;
- точка содержит основной текст, дополнительный текст, метаданные, фото и два аудиофайла.

Все ID стабильны и должны быть уникальны в своей области. ID точки и аудиоистории уникален глобально.

## Добавление направления без изменения приложения

1. Создать папку страны или города по существующему примеру.
2. Заполнить `manifest.json`, тексты и `meta.json`.
3. Для фотографии указать `media.photo.path`, `download_url` и `source_url`.
4. Для достопримечательности указать `map.navBounds`, `map.center` и путь `map.archive`.
5. Добавить ссылку на новый узел в родительский manifest и `content/catalog.json`.
6. Запустить три общих media-скрипта и сборку.

`tools/content_model.py` валидирует дерево. `tools/build_content.py` создаёт JSON, который читает универсальный UI. `tools/pack_media.py` собирает только бинарные файлы в Release ZIP.

## Пакеты и зависимости

Каждая страна имеет пакет уровня `country`, каждый город — пакет уровня `city`. Город объявляет `requires` на общий пакет страны. Клиент хранит только список установленных городов; зависимости вычисляются по манифесту, поэтому общий пакет нельзя случайно удалить, пока он нужен другому городу.

## Редакционные статусы

Структурная готовность не означает фактологической проверки. Поля `content_status`, `factcheck_status`, `source_candidates_unchecked` и редакционные документы сохраняются отдельно от механизма доставки.
